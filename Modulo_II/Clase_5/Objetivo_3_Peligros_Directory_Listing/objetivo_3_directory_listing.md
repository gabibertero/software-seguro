# Peligros del Directory Listing

Cuando alguien solicita una dirección que apunta a un directorio, por ejemplo `/archivos/`, el servidor busca primero un archivo de índice, como `index.html`. Si no lo encuentra y el listado de directorios está habilitado, genera una página con las entradas de ese directorio. Según la configuración, puede mostrar nombres de archivos y subdirectorios, tamaños y fechas de modificación. En Apache esto puede habilitarse con `Options Indexes`; en Nginx, con `autoindex on`.

El listado no necesariamente da permisos nuevos sobre los archivos, pero hace más fácil descubrirlos. Si el servidor también permite acceder a esos recursos, podrían quedar expuestos archivos de configuración como `.env`, copias de seguridad (`.bak`, `.old`), volcados de bases de datos (`.sql`), registros, código fuente, archivos comprimidos o datos de control de versiones. Estos archivos pueden contener credenciales, claves, rutas internas o información de usuarios.

Para mitigarlo, se debe deshabilitar la generación automática de listados (`Options -Indexes` en Apache y `autoindex off` en Nginx), y configurar un archivo de índice cuando corresponda. Esto no reemplaza los controles de acceso: los archivos sensibles deben quedar fuera del directorio público, las copias temporales deben eliminarse y el servidor debe bloquear el acceso directo a rutas y extensiones privadas. También conviene comprobar desde el navegador que solicitar un directorio sin índice no revela su contenido.
